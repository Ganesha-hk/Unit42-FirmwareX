# Contributing

Create a branch for a focused change, describe the behavior and scope, run scripts/test.sh, then open a pull request with test results and limitations. Review changes to sandbox permissions, output redaction and resource limits carefully. Do not commit credentials, input firmware, extracted filesystems, live databases or generated evidence to the source repository. Preserve documented incomplete outcomes rather than changing labels to imply success. This workflow describes future review expectations; it does not claim that historical commits received independent review.
